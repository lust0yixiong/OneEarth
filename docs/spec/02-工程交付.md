# 两阶段工程交付

本篇保存重构启动时的交付顺序和验收边界。当前可执行的 Mac mini 部署与恢复步骤见[部署手册](../部署与恢复.md)，已签收范围见[版本验收档](../../evidence/product/ACCEPTANCE.md)。

## 第一阶段 · Mac mini

在 `TestProjects` 开工。现有 `oneearth-app/` 工程和 5174 部署全程只读。新工程建议使用同级 `oneearth-next/`，已有目录先核实归属。新服务使用独立端口、可写数据目录、数据库和缓存。引用原型文件时复制到新工程，避免通过可写链接或挂载回写原型。安装依赖、构建、运行测试、截图输出和数据恢复均在新工程或隔离副本中进行。原型启动项、配置、`dist`、数据库、运行进程和入口保持原状。绝对路径、服务地址、凭据与桌面登录状态通过部署配置处理。

联调时先识别原型实际使用的执行器、模型、端点及其凭据来源，让新进程引用已有授权配置，再做最小真实调用。原型已有的授权直接沿用。遇到拒绝时先核对新进程的凭据加载方式、登录身份、端点及资源范围，只报告仍需续期或新增授权的具体链路，并行推进可做工作。

| 次序 | 实际工作 | 可检查的交付物 |
| --- | --- | --- |
| A1 | 核对当前部署版本、模型/执行器及 Search/Fetch 配置。采集原型首页、Chat、球体、来源与预览的代表状态；保存可复用的品牌与样式资源位置。记录历史数据和性能基线。 | 同一视口和状态下的界面基准截图，附原型版本或资源指纹、浏览器、测试条件及脱敏配置摘要。 |
| A2 | 在新工程明确运行时任务接口、发现服务协议与事件、执行器适配器。先接通真实执行器和独立启动的数据发现服务，再验证首问与追问。 | 可运行的后端、接口定义及集成测试。服务调用能追踪到同一任务；阶段结果和渠道错误能独立传给前端。 |
| A3 | 实现后台执行、任务状态保存和网页断线续接。接入时空数据服务、PostGIS 索引、图层文件存储与现有海纳读取路径。从一个确有数据的区域与时段开始，打通前端直取图层。 | 网页、运行时、发现服务与时空数据服务实际连通。能查一份真实资料、回到地球查看已有数据、按范围和时段取数。 |
| A4 | 按同一发布版本在隔离目录重新构建、建库和启动，变更端口与可写目录验证配置生效。在副本演练样例任务记录与图层索引、文件的导出和恢复。运行测试与类型检查，以真实浏览器做新旧界面和功能对照。 | 新工程目录、版本、入口、截图对照、构建和启动命令、脱敏配置模板、数据恢复记录及 ECS 交接记录。 |

功能拆分以 01 的目标接口为准。优先复用能保持现有外观与行为的样式、资源和组件，再按新架构调整内部实现。ECS 交接记录列出 Linux 与目标 CPU 的依赖、无桌面会话下的执行器认证方式，以及网络、数据库和对象存储的配置差异。Linux 可用时，阶段一就在该环境从同一源码版本干净构建、启动并测健康接口；仅有 macOS 时，记录已经做过的隔离复部署、尚缺的环境和可在 ECS 上直接复跑的命令。

产品版本验收需核对实际代码归属。网页负责输入、呈现与订阅；运行时维护任务，模型结合当前目标与真实结果选择动作，执行器通过适配器委托服务并回传结果。发布启动流程支持从新系统的部署配置注入用户已授权的凭据，在没有原型目录和原型启动项的环境中复部署。机构登录若受外部条件限制，记录受影响的发布范围，继续其余工程工作。

## 第二阶段 · ECS

开始前需要阶段一新工程的发布版本和可复现命令、ECS 的受控连接方式和 CPU 架构、可使用的网络/域名与登录入口，以及数据库和对象存储的可用位置。用户可提供 SSH 别名或密钥管理系统中的引用。云端迁移按阶段一的新工程版本和数据范围进行。正式切换窗口届时确认，导入原型历史记录仅在用户另行指定时开展。交接文件不存储明文密钥。

| 次序 | 实际工作 | 可检查的交付物 |
| --- | --- | --- |
| B1 | 验证 ECS 到机构登录系统、海纳、只读断言库、受控模型和 Search/Fetch 的真实连通性。在目标架构上从同一源码版本构建，按环境注入配置。 | 云端版本标识、服务健康记录、逐项连接结果。Mac 专属的执行器登录或命令路径要在 Linux 上独立验证。 |
| B2 | 将阶段一验收的新版本部署到云端验收入口，转移该新系统获授权的任务记录、索引和图层文件，核对引用与文件的对应关系。旧浏览器记录继续使用兼容样例验收。 | 可登录的新系统云端验收地址、发布版本、迁移记录和抽查证据。 |
| B3 | 重跑 03 同组用例，做多人问答与图层浏览混合压测、备份还原及回退演练。 | 实际负载与响应曲线、外部配额限制、可验证的恢复步骤、正式切换和处理新增写入的方案。 |

阶段一可独立验收。阶段二使用同一发布基线，若出现 Linux 兼容问题，在新工程修复并重测。真实 ECS 未提供时不得把本地模拟列为 ECS 部署成功。新购资源和云端生产入口切换待具体授权。两个阶段均保留原型工程、原型数据和 5174 部署。
