# OneEarth 重构的目标与架构边界

## 目标

OneEarth 围绕科学问题，关联研究路径、论文报告的数据集用法与可取得的数据实体，使研究者和模型能在时空上下文中发现、引用和使用多源地学数据。实体逐步积累。平台规划从约 130 万篇核心论文提取相关断言，这个规模是建设目标；交付时按实际接入量报告。仅有论文线索也有研究价值。论文研究区与数据集实际覆盖范围分别表达。

本次工程分两步。先在 Mac mini 交付可运行、可独立部署的重构版，再把同一版本迁到 ECS。面向未来多团队、约 100–300 人同时使用。容量须实测，同时在线人数和同时运行的 AI 任务数分别记录。

现有原型、Mac mini 重构版、ECS 部署有不同角色。原型提供界面与交互基准、可复用代码和兼容样例。第一阶段独立建设新系统，以目标架构确定服务边界和数据模型。第二阶段交付同一新系统的云端部署。兼容旧记录可以用样例验证；原型数据是否实际迁入，由用户另行决定。

阶段一交付研究者可以实际使用、团队可以持续维护和发布的 OneEarth 产品。Mac mini 和 ECS 是同一产品的两个部署环境。界面、球体及正确的领域代码可以复用。运行时、发现和时空服务按各自职责工作，发布版本有独立的配置入口，研究者经获授权的网页入口完成真实工作。

## 已确认的职责与调用关系

| 组件 | 负责什么 |
| --- | --- |
| OneEarth 网页前端 | Chat、来源及网页/PDF 预览、球体和交互。提交问答和续接进展调用运行时任务 API。已有图层直接向时空数据服务取数。 |
| OneEarth 运行时 | 以模型和执行器驱动本轮问答。按本轮目标、引用对象和已取得的材料决定下一步。维护任务身份，向网页交付真实进展、阶段结果或错误。运行时任务 API 是它的对外接口，网页直接使用。 |
| 执行器与适配器 | 运行时使用统一的执行器接口。Codex、Claude Code 等由各自适配器接入，明确支持的模型、能力和实际使用的组合。执行器通过协议委托数据发现服务，工具与按需加载的 Skill 可扩展。 |
| 独立数据发现服务 | 拥有研究问题、研究路径、数据集线索的发现逻辑。运行时可开始或继续发现，读取部分结果。服务决定检索内部的渠道选择与重试，及时返回带出处的线索和各渠道状态。论文断言库是服务内部的只读知识来源。海纳目录检索、网页 Search 和 Fetch 是可用工具。 |
| 时空数据服务 | 管理实体与版本的空间、时间索引及可视化图层。海纳在上游提供目录和原始文件。服务管理对象存储中的概览、分块和其他图层文件，以 PostgreSQL + PostGIS 保存范围、时段、版本和文件位置。浏览器按视野、尺度、时间取数并渲染，多人可复用已有产物。 |
| 后台执行与任务状态 | 慢检索在后台继续，地图读取独立响应。刷新网页可接回同一次任务，已取得的资料可继续查看。身份和访问权限对接用户已有的登录权限系统。外部模型 API 按授权的数据范围调用。 |

## 必须保留

- **凭据复用已获授权。** 新工程可以直接使用原型已配置的模型 Key、执行器登录，以及机构登录、海纳、断言库和 Search/Fetch 已有的访问权限。沿用原身份可访问的数据范围和外发边界，断言库保持只读。由新进程通过已有凭据来源直接连接相应服务，记录配置名称和调用结果，密钥值仅在运行时使用。

- **现有原型全程只读。** 现有工程、运行中的 5174 服务、启动项、配置、构建产物和业务数据均受此约束。重构在独立新工程进行，只读参考现有资料，按需将可复用文件复制到新工程。其他会话仍可正常使用原型。
- **界面继承原型。** 以用户已使用的部署版为视觉基准，继承 OneEarth 标识和标语、导航与面板布局、现有配色、字体层级、图标与间距，以及地球、Chat、来源和预览的主要交互。前端组件与数据接口可以重构。按基准判断视觉偏差；主动改版另行讨论。
- **从第一阶段就具备迁移条件。** Mac mini 是重构版的第一个部署环境。Mac 与未来 Linux ECS 共用代码、服务接口和发布版本，通过配置切换地址、凭据、数据库、对象存储和可写目录。分别记录操作系统与处理器架构所需的构建依赖。
- 每轮结合目标和明确的引用对象决定是回答、读取、发现、澄清还是操作地图。能由已有资料回答的追问直接使用该资料。必要检索渠道、模型和 Search/Fetch 配置保持可核对，变更这些条件需单独说明并经用户确认。
- 转换研究问题前须求证并取得用户确认。来源保持「本地数据集／文献依据／网页来源」三类，能解释并打开历史引用。每条进展对应真实发生的工作；部分失败保留已得结果。
- 断言始终只读。新增缓存、索引、任务记录和测试数据使用独立可写位置。海纳原始文件及现有机构登录能力继续复用。

## 留待以后讨论

数据治理和数据处理是各自独立的未来能力，各自保留接入位置。首期不建设数据核验业务、通用治理平台、处理平台或用户工具市场。跨团队共享和长期保存策略、DOI 与实体标识规则、Ganos 选型、正式 ECS 台数及规格均未定。为让首期跑通而采用的内部标识、协议或存储配置，在交接中标为可替换的工程选择。

## 文档优先关系

用户在新对话里给出的最新决定优先。新对话以本包文字确认目标和验收，附图帮助理解服务边界。旧系统中的代码、截图、部署说明和早期方案是复用与回归材料。若旧草案与这里冲突，按此处边界实施；若涉及改变用户已定目标，先指出具体冲突。日常实现细节由执行者决定并记录。

每次完成一个里程碑，在新工程的交付记录里对照 02 的交付物和 03 的验收项，写下实际证据及缺口。用户后续改变方向时，单独记下变更依据和影响的验收项。本交接包保留为启动时的基线，具体实现遇到困难由风险和阻塞记录反映。
