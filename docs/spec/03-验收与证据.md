# 验收与证据

在新工程保存一份持续更新的验收记录。每项写明版本、运行环境、访问入口、可重跑的命令或步骤、实测结果及证据位置。区分真实调用、故障注入和模拟测试。凭据、受限原文与用户私有对话不进入报告。

## Mac mini 核心验收

原型用于只读对照。打开公开页面可取视觉基准；问答、会话写入、故障注入、缓存清理和压测等在新工程或专用副本执行。采集基线需要写入时，使用隔离副本并注明与现网的差异。截图、测试结果和性能输出保存到新工程。
随包附上从 `http://127.0.0.1:5174/` 采集的两张原型实图。[首页与 Chat 展开](界面参考/首页与Chat.png) 和 [Chat 收起后的地球工作区](界面参考/地球工作区.png) 均取自独立浏览器会话，使用 Chrome 157.0.8103.79、1512 × 859 视口、DPR 1，前端入口为 `/assets/index-DpY_7JXa.js`。图中只有公开首页问题。实施时用可复现的样例补齐回答、来源预览和选格状态，记录正在比较的部署版本。

| 验收场景 | 可以观察和复查的证据 |
| --- | --- |
| 界面和配色继承 | 用同一浏览器、视口、缩放及可重复的内容，分别采集原型和重构版的首页、Chat 问答、来源和预览、地球与选格状态。并排核对标识、标语、色彩、字体、布局、间距、图标与主要交互。实时数据和时间变化单独标注。交付配对截图及差异处理结果。 |
| 首问与连续追问 | 首问从实际网页进入独立发现服务，返回带出处的真实材料。首答列出至少两篇论文时，追问「第二篇论文用了什么数据？」能定位到同一来源。原文足以回答时，按任务调用记录确认新增发现任务为零。记录所用执行器、模型及渠道。 |
| 问题转换与渠道 | 提议转换原问题后等待用户决定，确认前没有对新问题发起检索。检查看到的本地数据集、文献、网页的分类与出处及一条历史引用。 |
| 早到结果、局部失败与刷新 | 取得一条真实线索后刷新页面，核对任务编号及记录，旧结果可见，新进展继续，已执行的检索没有重复发出。用受控单渠道故障验证先到的线索仍可访问，并能看出哪个渠道失败。 |
| Chat、来源与球体 | 用真实浏览器打开首页、Chat，输入、滚动长回答、打开网页/PDF 预览再返回。检索进行中拖动、缩放、选格、切换年份、高亮与 flyto。检查响应、视野和选中状态，并核对图层直取、网络载荷、可见分块复用。 |
| 程序交付和部署 | 在隔离目录按说明建库、构建、启动和重启。核对前端、运行时、独立发现服务、时空数据接口和图层存储的实连情况；通过适用的测试与类型检查。记录当前独立入口和复现命令。 |
| ECS 迁移准备 | 从阶段一发布版本出发，在新目录通过配置更换端口与数据位置后启动，恢复样例记录及关联图层并实际打开。交付脱敏配置模板、备份恢复命令、Linux/CPU 与执行器依赖、逐项实测或待测状态。有 Linux 环境时附上构建和启动日志；真实 ECS 的部署与压测在第二阶段验收。 |

验收新系统独立运行时，在测试副本的客户端和服务端限制访问原型 5174，保持原型在线。从新入口实际发起问答、读取图层并检查调用记录。新服务可按授权读取共同上游（海纳、只读断言库等），业务请求应由新工程的相应服务处理。原型历史记录兼容测试使用样例，批量搬入原型数据不作为这项验收的条件。

### 产品版本验收

- 从真实用户入口连续完成研究操作，记录模型选择的动作、执行器适配器发出的服务调用、部分结果和后续动作。使用未为验收专设处理分支的自然提问与追问，包括材料不足时需要继续读取或发现的情况。
- 独立复部署时，为新进程显式注入同一套已授权凭据，验证运行不依赖原型目录、启动项或 5174。这个验证在新环境进行，现有原型继续运行。
- 分列本机功能验证、真实用户与项目权限验证、实际客户端访问和云端验证。机构测试身份缺失时注明具体依赖；产品自身的权限接入和其余可测试工作继续进行。

### 使用哪些问题

首批选 3–5 个自然问题，包含首问和追问。可直接采用原型 `src/domain/chat-home.ts` 中的川西地表形变、西北太平洋海表温度与海色、大兴安岭森林结构三题，再加上述第二篇论文追问。`scripts/fixtures/research-acceptance.json` 还有成组的首问和追问。样本条件相同才对比；若实际结果缺少第二篇论文，选有两篇可读论文的实测样本并注明。

### 怎样记录性能

- 使用同一模型、渠道和样本，注明冷/热缓存、是否局域网客户端、浏览器版本和网络条件，做有样本数的重复对照。记录分布或范围；样本少时直接列出各次耗时。
- 问答分别记录请求、服务端排队、首次真实检索进展、首段真实回答和回答完成的时间。标明前端动画时间。可观测到的检索、模型、传输、主线程开销分别列出，其余明确为未分解。
- 球体在空闲和后台检索两种条件下做相同动作，记录交互帧间隔、慢帧、图层加载时间及传输量。服务器本机与局域网 Safari 分列。没有新的真实客户端样本时保留这个缺口，继续其余验收。
- 此前在 MacBook Pro 的局域网 Safari 上，交互帧间隔 P95 两次采样分别为 141 ms 和 53 ms，两次手势分布、请求量和网络条件不同。这两条是历史线索，新版仍须建立自己的对照。原型已有 `scripts/globe-performance-check.mjs` 和 `scripts/globe-motion-check.mjs` 可供复用。

## ECS 增量验收

同一组问答与球体操作须在真实 ECS 上复测。记录在线浏览人数、同时执行的 AI 任务、模型和检索配额；逐步增加混合负载，给出实测达到的范围、排队时间、真实首段延迟和可见图层加载时间。目标规模为 100–300 人同时使用，只对实际覆盖的负载作结论。用恢复出的副本打开一条研究记录和一个图层，核对版本、引用与访问控制。给出可执行的回退步骤并说明如何处理切换后的新增写入。

## 完成与交接

阶段交付时逐项标注「通过／失败／外部条件未具备」，附证据。核心工作未完成时继续处理可做事项。只有在实际尝试复用原型已有凭据和权限后，仍需续期、扩大授权或补充外部资源时，才将相应链路记为受阻。报告脱敏的连接结果、影响范围及最小缺失输入，并继续其他可验证工作。代码实现、模拟通过、真实环境验收分别报告。

阶段一交接记录至少写齐新工程位置、发布版本、独立入口、构建与启动命令、数据和凭据的配置名称、已测执行器组合、验收证据及 ECS 待办。阶段二据此接手，无需前一段对话。
