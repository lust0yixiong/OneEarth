# OneEarth 部署与恢复

本手册适用于当前 Mac mini 产品。选用发布源码时，先核对[当前架构与版本](架构与接口现状.md)和[该版本验收记录](../evidence/product/ACCEPTANCE.md)。在自己的隔离目录运行复跑命令。现有常驻 5474 和原型 5174 各自使用已有实例。

## 输入与授权

| 输入 | 从哪里取得及如何核对 |
| --- | --- |
| 源码、依赖与静态构建 | 固定 Git 提交，按 [Node 版本](../.node-version)安装 Node.js，使用锁定依赖，以 `npm run build` 产出 `dist/`。交接附提交号、构建与校验清单。 |
| 基础地图库 | 使用获准的独立副本。数据目录包含 `grid-data/`、`s2-data/`、`imerg/catalog.json` 和所选年月下的 IMERG 图层输入。已有基础输入可直接设置 `ONEEARTH_DATA_DIR`。 |
| 持久存储 | 运行时、发现、时空各用一个产品 PostgreSQL 18 库，时空库预先启用 PostGIS。图层用独立 S3 兼容桶及对象前缀。Mac mini 可使用 [Postgres.app 的命令行工具](https://postgresapp.com/downloads.html)及 [Garage](https://garagehq.deuxfleurs.fr/documentation/quick-start/)。 |
| 上游与模型 | 外部授权通过 `ONEEARTH_CREDENTIALS_FILE` 的绝对路径或部署环境注入。发现进程单独设置 `ONEEARTH_DISCOVERY_CHAT_MODEL`。运行时使用本机另有授权的执行器及模型。论文断言连接只读。海纳的原始数据由上游保存。实际开放渠道依各自授权与配置。[配置模板](../.env.example) · [工具边界](发现服务-A2A.md#公开网络工具的运行时执行) |
| 观测原件与登记 | 受权的原件、版本、SHA-256、登记与来源绑定单独交接。运行时通过 `ONEEARTH_SKILL_REGISTRY` 取得注册表。需要验证观测执行时，按协议注入相应的 `ONEEARTH_SKILL_SERVICE_TOKEN` 等配置，核对路径、摘要、变量和授权。[观测来源契约](发现服务-A2A.md#从已保存来源读取已登记的-netcdf-文件) |
| 复验证据 | 验收记录包含版本和证据索引，部分原始证据留在执行机器的受控目录。历史 706 题工作簿为相应测试的外部输入，科学问题案例页保持空白。 |

可在独立源码目录运行 `npm run data:prepare -- /absolute/authorized/globe-data`，从实际具备输入的目录复制到**当前源码工作树**的 `.local/globe-data`。脚本默认复制 2023、2024，其他可用年份通过 `ONEEARTH_IMERG_YEARS` 设置。该参数是**源目录**。核对目录和逐月资产后再把 `ONEEARTH_DATA_DIR` 指向这份副本。[复制实现](../scripts/prepare-inputs.mjs)

沿用原型已有授权时，在有权读取原配置的研发工作区一次性执行 `npm run access:import`。生成的 `~/Library/Application Support/OneEarth Next/access.json` 仅当前用户可读，独立部署通过文件引用或同等配置使用。生产启动保持 `ONEEARTH_USE_EXISTING_ACCESS=0`。本机执行器登录和上游凭据需要单独可用。

## 端口

| 场景 | 工作台后端公开入口 | 发现 | 时空 | 同一工作台后端的回环兼容口 | PostgreSQL／Garage |
| --- | ---: | ---: | ---: | ---: | --- |
| 常驻 primary | 5474 | 5475 | 5476 | 5477 | 55432／5900 |
| 初次隔离示例 | 5894 | 5895 | 5896 | 5897 | 55442／5940 |
| 恢复示例 | 5574 | 5575 | 5576 | 5577 | 55433／5910 |

先确认端口可用。默认 [启动器](../scripts/launch.mjs)启动一个工作台后端及独立的研究 worker、发现和时空进程。工作台后端使用两个不同的监听端口，上表另两端口由发现、时空使用。原型的 5174 留给原型。

`node scripts/launch.mjs workbench` 单独启动合并后的工作台后端，需要运行时数据库及既有依赖。显式 `node scripts/launch.mjs web runtime` 保留拆分时的诊断启动，分别承担网关和运行时 API，不能与 `workbench` 在同一次启动中组合。常驻启动项和隔离示例均使用无角色参数的默认启动。

## 首次隔离部署

以下示例在独立源码目录与干净的终端环境执行。已有环境变量优先于 `--env-file`，切换实例时核对三库、对象桶及状态路径确实属于目标。先将示例中的路径替换成已准备好的绝对路径。Mac 的 Garage 默认查找 `/opt/homebrew/bin/garage`，可用 `ONEEARTH_GARAGE_BIN` 指定其他位置。先准备授权文件和执行器登录，再运行实际调用。

```sh
(
  set -e
  npm ci
  npm run check
  npm test
  npm run build
)
```

```sh
(
  set -e
  oneearth_home="$HOME/Library/Application Support/OneEarth Next"
  export ONEEARTH_PG_BIN_DIR=/absolute/postgres18/bin
  export ONEEARTH_DATA_DIR=/absolute/prepared-globe-data
  export ONEEARTH_CREDENTIALS_FILE="$oneearth_home/access.json"
  export ONEEARTH_USE_EXISTING_ACCESS=0
  export ONEEARTH_DISCOVERY_CHAT_MODEL='{"executor":"codex","model":"deepseek-flash","provider":"deepseek"}'
  export ONEEARTH_HOST=127.0.0.1 ONEEARTH_LAN_INTERFACE=
  export ONEEARTH_PORT=5894 ONEEARTH_DISCOVERY_PORT=5895
  export ONEEARTH_SPATIAL_PORT=5896 ONEEARTH_RUNTIME_PORT=5897

  node scripts/macos-product-storage.mjs init isolated-first 55442 5940
  deploy_config="$oneearth_home/storage-isolated-first/deployment.env"
  node --env-file="$deploy_config" --import tsx scripts/migrate-paper-catalog.ts --initialize-empty
  node --env-file="$deploy_config" scripts/launch.mjs seed
  node --env-file="$deploy_config" scripts/launch.mjs
)
```

`init` 为该实例创建三库、PostGIS、对象桶及专用状态配置。初次运行先初始化空目录发布状态，再导入实际可用的图层。确认 [5894](http://127.0.0.1:5894/) 的版本和图层。有授权时核验一笔公开资料问答及其引用。需要核对原型隔离时，在上述子 shell 内将最后一条启动命令替换为 `node --env-file="$deploy_config" scripts/start-isolated-release.mjs /absolute/prototype-directory`。前台进程用 Ctrl+C 停止，已初始化的存储用 `node scripts/macos-product-storage.mjs start isolated-first` 单独启动。[存储初始化](../scripts/macos-product-storage.mjs)

## 常驻运行与发布

Mac mini 的常驻实例使用 `launchd`。已签收源码和静态构建落在 `~/Library/Application Support/OneEarth Next/releases/` 下的版本目录。独立基础数据采用专用 `base-data/`。常驻 `storage-primary/deployment.env` 保留产品库、对象桶与已有应用状态的引用。记录实际源码、构建和部署配置摘要。

在具有常驻部署权限的 Mac GUI 会话中完成安装。换版先确认队列排空，保存旧发布和启动项，执行停写备份，核对实际注入的独立发现模型、凭据来源以及当前配置，再切应用。应用与存储日志位于 OneEarth 数据根的 `logs/`。

```sh
(
  set -e
  oneearth_home="$HOME/Library/Application Support/OneEarth Next"
  node scripts/macos-product-service.mjs install "$oneearth_home/releases/<已签收发布目录>" "$oneearth_home/base-data"
  node scripts/macos-product-service.mjs status
)
```

已有应用用 `node scripts/macos-product-service.mjs restart` 重启。应用的暂停和启动分别使用 `stop` 和 `start`。安装或升级保留旧启动项中的部署环境值，并按新发布目录生成启动路径。原数据库、对象存储、模型配置和授权引用继续使用。回退时恢复旧发布与启动配置并沿用当下的持久存储。验收时核对 5474 和 5477 的监听 PID 一致，分别验证两种健康响应、旧研究、存档引用、事件续订和实际地图资源。[常驻管理脚本](../scripts/macos-product-service.mjs)

需要局域网时，在部署配置或应用的 `launchd` 环境设置 `ONEEARTH_LAN_INTERFACE`，同时保留 `ONEEARTH_HOST=127.0.0.1`。工作台公开入口同时监听本机回环与指定接口的唯一私有 IPv4。经直连网段、Host 与同源 Origin 校验后访问该地址的 5474。指定接口暂无合格地址时，回环仍可用，应用重启时重新识别地址。工作台的兼容口 5477、发现、时空、数据库和对象存储均使用回环。[本机与局域网实况](架构与接口现状.md)

## 备份和恢复

### 停写备份

先等待研究、目录导入和时空投影同步，再停止应用、导入命令及其他写入者。数据库与对象服务继续运行以便导出。记录所用发布与停写点。每次使用新备份目录，限制访问权限。

| 备份项 | 内容与核对 |
| --- | --- |
| 产品备份格式 3 | `product-backup.mjs export` 保存运行时、发现、时空三库，约定前缀中的图层对象及 `manifest.json`。清单含各库与对象校验、论文当前发布和历史版本状态，以及时空完整投影。脚本校验所取对象字节。 |
| 应用状态 | 停写后另存 `ONEEARTH_STATE_DIR` 和部署中显式指向其他位置的所需状态文件，保留 SQLite 伴随文件、目录结构和校验。记录绝对路径引用、启动项与部署配置的安全位置。 |
| 观测原件与登记 | 另存获准原件、对应的注册表和版本来源，验证原件 SHA-256。基础网格和用于重新播种的图层输入也需有独立副本或可重新获取的清单。 |
| 外部输入与授权 | 上游原始仓库、断言库、自有凭据、工作簿及留在其他机器的原始证据按各自权限单独交接。保存授权引用，避免将凭据或受限材料写入 Git。 |

确认导出使用源实例的实际 `deployment.env`，目标目录须可新建。下例还保存从配置核对出的已停写应用状态。登记、原件及显式配置到其他位置的文件按上表另存。执行器模型和运行凭据的备份与恢复遵从其原有授权。[备份与恢复脚本](../scripts/product-backup.mjs)

```sh
(
  set -e
  oneearth_home="$HOME/Library/Application Support/OneEarth Next"
  source_config="$oneearth_home/storage-primary/deployment.env"
  source_state=/absolute/stopped-app-state
  backup_dir=/absolute/new-backup
  export ONEEARTH_PG_BIN_DIR=/absolute/postgres18/bin
  umask 077
  mkdir -m 700 "$backup_dir"
  node --env-file="$source_config" scripts/product-backup.mjs export "$backup_dir/product"
  cp -pR "$source_state" "$backup_dir/app-state"
)
```

### 隔离恢复与验收

下例使用格式 3 备份，目标是新实例、空三库和空对象前缀。先恢复产品包，再在首次启动前把另存的应用状态复制到目标的独立状态路径，将获得授权的原件及登记指向恢复副本。遇到中断时保留失败目标供排查，在新空目标重试。

```sh
(
  set -e
  oneearth_home="$HOME/Library/Application Support/OneEarth Next"
  backup_dir=/absolute/saved-backup
  export ONEEARTH_PG_BIN_DIR=/absolute/postgres18/bin
  umask 077
  node scripts/macos-product-storage.mjs init restored 55433 5910
  restore_config="$oneearth_home/storage-restored/deployment.env"
  restore_state="$oneearth_home/storage-restored/app-state"
  test ! -e "$restore_state"
  node --env-file="$restore_config" scripts/product-backup.mjs restore "$backup_dir/product"
  cp -pR "$backup_dir/app-state" "$restore_state"
)
```

核对 `restore_config` 中的 `ONEEARTH_STATE_DIR`、三库和对象桶均属于恢复实例。配置有权限使用的外部凭据、观测注册表及执行器。启动命令使用恢复实例的四个端口。

```sh
(
  set -e
  oneearth_home="$HOME/Library/Application Support/OneEarth Next"
  restore_config="$oneearth_home/storage-restored/deployment.env"
  export ONEEARTH_DATA_DIR=/absolute/restored-globe-data
  export ONEEARTH_CREDENTIALS_FILE="$oneearth_home/access.json"
  export ONEEARTH_USE_EXISTING_ACCESS=0
  export ONEEARTH_DISCOVERY_CHAT_MODEL='{"executor":"codex","model":"deepseek-flash","provider":"deepseek"}'
  export ONEEARTH_HOST=127.0.0.1 ONEEARTH_LAN_INTERFACE=
  export ONEEARTH_PORT=5574 ONEEARTH_DISCOVERY_PORT=5575
  export ONEEARTH_SPATIAL_PORT=5576 ONEEARTH_RUNTIME_PORT=5577
  node --env-file="$restore_config" scripts/launch.mjs
)
```

源与目标服务都启动后，从新浏览器比对同一研究、依据与图层。已有[恢复验收脚本](../scripts/accept-product-restore.mjs)需要一个实际包含论文依据的历史任务 ID，并检查森林图层。使用相同发布、不同入口和单独的证据目录。另对公开 Landsat 归档、实际发布的 IMERG 年月和瓦片取样。有获准 KEO 原件和登记时，按归档版本验证 WSPD 非缺测数与时间边界，QC、风流配对和通量离线复算按科研证据单列。[验收与证据](spec/03-验收与证据.md)

### 论文目录发布、旧格式与回退

有授权的完整文献目录可以用下列命令发布到首次隔离实例。另一个入口 `scripts/sync-assertion-postgres.ts` 通过原有只读连接取材，并向配置的发现 PostgreSQL 发布。当前映射更新保留历史内容 ID，时空服务按代同步，失败时可继续用上一个完整投影。

```sh
(
  set -e
  deploy_config="$HOME/Library/Application Support/OneEarth Next/storage-isolated-first/deployment.env"
  node --env-file="$deploy_config" --import tsx scripts/sync-assertion-catalog.ts --import /absolute/catalog.json
)
```

格式 2 恢复由备份脚本从包内密封 SQLite 快照迁移。复制另备的历史应用状态前，在独立副本中将旧 `paper-evidence.sqlite` 及其伴随文件另存，当前应用状态使用 PostgreSQL 发布目录。格式 1 只能利用归档发现任务有限重建旧目录，原发布集合与顺序不能从该格式完整验证。历史仍使用纸本 SQLite 的原地升级，先停写并用上一版生成格式 2，再迁移到产品发现库。

```sh
(
  set -e
  deploy_config=/absolute/approved-target/deployment.env
  node --env-file="$deploy_config" --import tsx scripts/migrate-paper-catalog.ts --sqlite /absolute/backup/paper-evidence.sqlite
  node --env-file="$deploy_config" --import tsx scripts/migrate-paper-catalog.ts --status
)
```

回退常驻应用先排空和停写，再核对已有新写入与旧版本的兼容性。能兼容时恢复旧发布及启动配置并沿用当前 primary。留存切换后产生的记录、库和对象。确需回退至旧的 SQLite 论文目录时，先从当前产品库用新版本的 `--export-sqlite /absolute/new/compatibility.sqlite` 导出兼容快照，留存旧文件及伴随文件后再换入启动。以另一个空实例演练冷恢复、引用和图层后，再确认回退方式。

真实 ECS 的部署、授权、并发和数据切换使用独立环境验收。[两阶段交付基线](spec/02-工程交付.md#第二阶段--ecs)
