# 时空数据服务接口契约

时空服务维护覆盖范围的权威修订、网格索引及已发布图层的分块清单。浏览器和局域网调用方使用工作台同源地址。当前 5474 代理 `/api/coverage/*`、`/api/spatial/*` 和已挂载的图层资源路径。时空进程本身监听 IPv4 回环 5476。运行时内部的选格取证客户端直接访问时空进程。覆盖查询按当前发布目录及原范围计算，分块查询按图层的空间和时相索引匹配。[网关代理](../server/runtime-workbench-queries.ts) · [图层资源网关](../server/index.ts) · [时空入口](../server/spatial-service.ts) · [部署端口](部署与恢复.md#端口)

## 覆盖查询与网格

### 三步发起查询

以下命令需要 `curl` 和 `jq`。示例使用上海附近的 H3 R2 单元格及当前目录，依次读取实际修订、登记范围、取单格数量及可定位成员。工作台实例须已完成覆盖目录初始化。

```sh
base=http://127.0.0.1:5474

revision=$(curl -fsS "$base/api/coverage/revision" | jq -er '.revision')

scope=$(jq -n --arg revision "$revision" '
  {revision: $revision, filters: {
    need: -1, type: "", source: "", place: "", period: null, depth: null, maxDem: null
  }, batch: null}
' | curl -fsS -H 'Content-Type: application/json' \
  --data-binary @- "$base/api/coverage/scopes")

scope_id=$(printf '%s' "$scope" | jq -er '.id')
scope_revision=$(printf '%s' "$scope" | jq -er '.revision')
jq -n --arg id "$scope_id" --arg revision "$scope_revision" '
  {
    id: $id, revision: $revision,
    grid: {system: "h3", n: 2, key: "h2", label: "H3 R2"},
    cells: ["82309ffffffffff"],
    includeProducts: true, includeReferences: true
  }
' | curl -fsS -H 'Content-Type: application/json' \
  --data-binary @- "$base/api/coverage/cells"
```

### 修订和范围

| 入口 | 输入与返回 |
| --- | --- |
| `GET /api/coverage/revision` | 返回 `{revision}`，当前实现为 64 位小写十六进制修订。覆盖投影不可用时返回 503。 |
| `POST /api/coverage/scopes` | JSON `{filters, revision?, batch?, selection?}`。传入 `revision` 时要求与当前版本一致。返回 `{id, revision, scope}`。 |
| `POST /api/coverage/cells` | JSON `{id, revision?, grid, cells, includeProducts?, includeReferences?, requireSelection?}`。用范围响应中实际签发的 `id` 和 `revision`。返回同修订的计数、已就绪格及按需读取的成员与来源。 |

- `scopes` 与 `cells` 使用 `Content-Type: application/json`，请求体上限均为 2 MiB。JSON 解析失败或超限时，当前实现由时空服务统一返回 503。
- `filters` 使用示例的完整字段。空字符串表示不按该项筛选，`need: -1` 允许全部需求。可选 `utcWindow` 为 UTC 毫秒时间戳的半开区间 `[起点, 终点)`。它与按年份筛选的 `period`、图层分块的起止日期各自独立。
- `batch` 省略或为 `null` 时查询当前目录。使用已保存的结果批次时传入原 `CandidateSet`，其中 `ids` 最多 10,000 项。服务会规范化批次 ID，且只使用当前或已缓存的原资料。默认指标是 `products`。原批次为 `scenes` 时统计逐景成员。
- `selection` 可从原批次携带，或作为顶层字段传入 `{id, grid, point}`。`point` 为 `[经度, 纬度]`。两处同时给出时，单元格与网格键须一致。模拟选择不予登记。已登记的选择固定该范围允许读取的单元格。
- 范围摘要 `scope` 包含 `filters`、`selection`、`caseId`、`layer`、`metric`、`candidateCount`、`candidateIdentity`。无批次时最后两项为 `null`。范围 ID 由时空服务在当前进程内签发，最多保留最近登记或重新登记的 32 个。修订变化、进程重启或范围被淘汰后要重新登记。

### 网格编号和响应

`grid` 使用 `{system,n,key,label}`。同一批请求传 1 至 512 个同系统、同层级的有效格 ID，服务去重后计算。

| 系统 | 支持层级 | 键与标签 | 单元格 ID |
| --- | --- | --- | --- |
| H3 | 2 至 7 | 如 `h2`、`H3 R2` | H3 单元格字符串，分辨率与 `n` 相同。 |
| S2 | 5、6、8、9、11、12 | 如 `s5`、`S2 L5` | S2 CellID 的十进制字符串，层级与 `n` 相同。使用字符串保全整数精度。 |

| 响应字段 | 含义 |
| --- | --- |
| `revision` | 本次计算使用的覆盖修订。 |
| `cells` | `[[cellId, count], ...]`，只包含正计数。 |
| `ready` | 本次已完成的格 ID，包含已确认零命中的格。只有位于 `ready` 且未出现在 `cells` 的格才能记为 0。 |
| `pending` | 本次尚未完成的格数量。对请求中未列入 `ready` 的格保留待计算状态，可用同一范围再查。 |
| `members` | `includeProducts: true` 时返回 `[[cellId, [memberKey, ...]], ...]`。只允许单格查询。 |
| `references` / `sourceIds` | 同时设置 `includeProducts: true` 与 `includeReferences: true` 时返回。`references` 按格和成员列出来源 ID，`sourceIds` 按格合并去重，最多 32 个。 |
| `scope` | `requireSelection: true` 时返回原范围摘要。范围须已登记真实选择，请求仅可读原格。 |

例如，若请求 `cells: ["82309ffffffffff", "8240e7fffffffff"]` 且省略成员和来源选项，下列响应表示上海示例格已确认无匹配，第二个格仍待计算。

```json
{"revision":"aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa","cells":[],"ready":["82309ffffffffff"],"pending":1}
```

覆盖响应使用 `Cache-Control: no-store`。应用自己的显示缓存时，同时绑定范围及修订，并丢弃已经失效的范围结果。[覆盖路由](../server/coverage-router.ts) · [请求和响应类型](../src/domain/coverage.ts) · [格号校验](../src/domain/context-validation.ts) · [网格计算](../src/data/evidence/research-grid.mjs)

## 图层目录和分块

`GET /api/spatial/layers` 直接返回按 `id` 排序的数组，每项含 `id`、`entity_id`、`version`、`title`、`source`。用列表中的 `id` 查询 `GET /api/spatial/layers/:layer/chunks`。以下命令使用代码中已有的 IMERG 分块样例，结果是否为空取决于实例发布的数据。

```sh
base=http://127.0.0.1:5474
curl -fsS "$base/api/spatial/layers" | jq .
chunks=$(curl -fsS -G "$base/api/spatial/layers/imerg/chunks" \
  --data-urlencode 'bbox=102,26,111,35' \
  --data-urlencode 'start=2024-07-01' \
  --data-urlencode 'end=2024-07-31' \
  --data-urlencode 'level=2')
printf '%s\n' "$chunks" | jq .
```

- `bbox` 为 WGS84 的 `west,south,east,north`，经纬度使用十进制度。经度范围为 ±180°，纬度范围为 ±90°，要求 `south < north` 和 `west != east`。`west > east` 表示跨越反经线。
- `start`、`end` 为实际存在的 `YYYY-MM-DD` 日期，要求起点不晚于终点。分块与请求时段有相交即匹配，包含两端。空间边界相交的块也可返回。
- `level` 为已发布图层的分块尺度，接受 `0`、`1`、`2`。返回 `{chunks:[{route,size,hash}]}`。`size` 是字节数，`hash` 是发布对象的 SHA-256，`route` 是实例供应的路径。结果按块起始日、路径排序，最多 2,048 条，响应无分页游标。大范围查询应拆分 bbox 或日期并按 `route` 去重。图层不存在或条件无交集时，可得到 `200 {"chunks":[]}`。

对象使用服务器返回的 `route` 访问，已发布家族包括降水 `/precip-data/*` 和已接入的海纳可视化资源。已索引对象响应带强 ETag，值为对象哈希加双引号。匹配 `If-None-Match` 时返回 304。普通索引对象的 JSON 清单为 `no-cache`，其他对象为 `public, max-age=86400`。独立 VIIRS 处理器有自己的缓存头，以实际响应为准。

```sh
# chunks 非空时，用首个 IMERG 分块验证条件请求
chunk_route=$(printf '%s' "$chunks" | jq -er '.chunks[0].route')
chunk_hash=$(printf '%s' "$chunks" | jq -er '.chunks[0].hash')
curl -sS -D - -o /dev/null \
  -H "If-None-Match: \"$chunk_hash\"" "$base$chunk_route"
```

## 错误与恢复

| 状态 | 何时出现 | 调用方处理 |
| --- | --- | --- |
| 400 | 范围筛选、格号、单格选项、分块 bbox、日期或尺度无效。未登记选格时使用 `requireSelection` 会返回 `coverage_selection_required`。 | 纠正字段或登记所需选格后再请求。 |
| 403 | 工作台访问地址、来源或同源校验不通过。 | 使用已获准的工作台地址。 |
| 409 · `coverage_revision_changed` | 登记范围时客户端传入的修订已旧。 | 读取新修订，以原筛选条件登记新范围。 |
| 410 · `coverage_scope_expired` | 读格时原范围失效，或提供的修订与当前修订不一致。 | 丢弃旧范围的缓存结果，重取修订、范围和网格。 |
| 404 | 请求路径没有对应的发布对象。 | 重读图层清单，核对原资源路径是否仍发布。 |
| 502 | 工作台代理无法连接时空服务，或对象字节长度校验失败。 | 根据响应错误区分代理与对象问题，保留失败状态。 |
| 503 | `coverage_unavailable`、`coverage_inputs_unavailable`，或图层索引及对象存储暂不可用。覆盖 JSON 解析失败或超限也返回通用 503。 | 覆盖保持未知。先核对请求的 JSON 和大小，再根据服务或原批次的状态重查。 |

修订冲突示例。响应中的 `revision` 为服务器当时所知的修订。

```json
{"code":"coverage_revision_changed","error":"覆盖数据已更新。","revision":"aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa"}
```
