# OneEarth 的 Skill 嵌套执行与验收

目标设计。基线为 Mac mini 的 rc.9 和架构提交 `9bb6ee7`。适用于业务智能体委托运行时执行的共享工具与 Skill，以下为隔离候选的验收要求。

**职责与返回路径。** 数据发现服务提出要解决的问题、允许使用的材料和所需能力。运行时核对调用归属、固定的能力版本及授权交集，通过内部适配层让执行器完成 A、B、C。若 A 调 B，B 再调 C，结果沿 C → B → A 返回，只有 A 的最终成果或受限结果交回原发现需求。发现服务据此决定下一步，保有自己的规划模型。适配层声明能否当场执行、暂停续接或独立执行，以及需要哪些资源。

**两端都能停下来。** 研究步骤保存发现委托的受理身份和已得材料，等待期间让出运行时 worker。发现服务提出能力需求时，保存需求编号、等到哪一步、输入版本、有效授权、已有证据及待解问题，让出发现作业名额。原 A2A 发现任务保持未完成，收到匹配该需求及等待序号的结果后，由后续作业继续。自动续接使用独立的机器事件；网页沿用原研究记录，需要改变研究目标或扩大授权时走人工确认。 可在两端等待时各排入一个须经相应 worker 的短步骤，核实两个名额都已让出。

**资源怎样安排。** 已授权的子步骤能在当前上下文中完成且无需重领父项占用的资源，可以当场调用。其余优先保存检查点、归还执行名额，再等待结果。不可暂停的调用如需独立子执行，启动前按准许的嵌套深度和并发一次预留实际受限资源；普通作业不能占用该预留。整条调用可以在取得资源前排队。已占资源且无法暂停时，超出预留的子调用立即返回“未启动”及原因。并发登记等待关系时须保证不会形成跨链循环。跨服务委托前结束持锁事务，固定输入版本，发布时复核。

**怎样恢复。** 首次外发前保存稳定调用编号及内容指纹。如果对方已受理而本端丢失回执，按原编号查证；下游支持幂等时可用原编号、原内容重送。采纳结果时，在同一事务中核对归属、等待序号与状态，保存产物和出处并登记唯一下一步。取消与采纳互斥。已确认取消后到达的结果不能唤醒任务，既得材料保留。外部副作用无法查证时记为“结果未知”，停止自动重试。

**首个案例。** 同一个发现任务请 A 判断观测资料是否满足指定单位和时间要求。A 请 B 核对指定文件，B 在运行中调用 C 读取变量单位和有效记录时段。测试方备好两个单位及时段不同的固定版本小文件，选其一；只有 C 读取文件。沿 C 的文件校验值、变量和记录，核对 B 的判断、A 的答复和交回原发现任务的出处。

| 条件 | 必须观察到的事实 |
|---|---|
| 仅一个运行时执行名额，A、B 可暂停 | A、B 依次保存检查点，退出当前执行并归还许可。C 领取同一名额，峰值占用为一。随后原 B、A 及原发现任务依次续接。 |
| A 不可暂停，已为子项预留容量 | 两条链实际占满普通名额，竞争请求拿不到 A 启动前绑定的专用名额。暂扣 C 的结果，同时看见 A 持普通名额等 B、B 在 A 的上下文中等 C、C 已领预留名额执行。执行收据显示 B 有独立调用编号、以 A 为父，C 的实际请求以 B 为父；B 未另领普通名额。放行后逐级核对产物。 |
| 另一条已运行的链没有预留，也不能暂停 | 在父项释放资源前收到明确的“子调用未启动”。该子调用无待执行作业，启动及外发均为零。释放容量、让调度器再次取件后，原调用仍未启动，原有材料可读。 |

在一条成功链上，模拟 B 已保存 C 的结果、回执尚未送达，再送同一结果。核实 C 只执行一次，B、A、原发现及引用各只推进或登记一次。同编号的冲突内容、过期等待序号均不得改档。另验首次受理丢回执、等待中重启、取消后结果晚到、跨链循环与父锁冲突。以持久记录、执行收据和资源实测相互核对。受控文件案例证明所测配置的执行名额和读取行为；供应商模型配额须有独立实测依据。
